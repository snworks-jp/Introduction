# 010 BLOGの構造改善（テーマ・楽器の分類／関連記事／まとめページ）

- 対象: BLOG（`scripts/release.py`、`scripts/template-curation.html`、`blog/index.html`、既存記事9本、`sitemap.xml`、記事案の書式）
- 優先度: 中（記事が増える前に仕組みを入れておく）
- 作成日: 2026-11-01
- 前提: 009（BLOGのデザイン統一）の実装後に着手するのがおすすめ。
  デザインと構造を同時に直すと、どちらの不具合か切り分けにくくなるため。
- 関連: 二階堂さんの承認済み（「1・4・8をおすすめどおり進める」）。ページ類（ScoreMate・カレンダー・プライバシー）のデザイン統一は別の依頼書（011）にする。

## 目的
記事が増えても「縦に伸びるだけの一覧」にならないよう、①悩み・楽器での分類、②記事の最後の関連記事、
③テーマ別・楽器月間のまとめページ を、`release.py` の自動生成で追加する。
手作業は増やさない（公開のたびにスクリプトが作り直す）こと。

## 提案内容

### 1. 記事の分類情報（meta）を追加する
現在の分類は `category`（`column` / `announcement`）だけ。これに、次の2つの `<meta>` を足す。

```html
<meta name="topic" content="long-tone">      <!-- 悩み・テーマ（1つ） -->
<meta name="instrument" content="all">       <!-- trumpet / trombone / horn / euphonium / tuba / all のどれか -->
```

- `topic`: 英小文字とハイフンのスラッグ。表示名は `release.py` 内の辞書（例 `TOPIC_TITLES`）で管理し、
  日本語表記はそこだけで決める。
- `instrument`: 特定の楽器の記事なら該当の楽器、全楽器共通なら `all`。表示名も辞書で管理。
- `category="announcement"`（お知らせ・記録の残し方）は、`topic` に `records`（記録・整理）を使う。
- 未指定（古い記事・メタがない記事）の扱い: `topic` は `other`、`instrument` は `all` として処理し、エラーにしない。

### 2. 既存記事9本への割り当て（案）
| ファイル | topic | instrument |
|---|---|---|
| long-tone.html | long-tone（ロングトーン） | all |
| lip-slur.html | lip-slur（リップスラー） | all |
| high-notes.html | high-notes（高い音） | all |
| tonguing.html | tonguing（タンギング） | all |
| practice-menu.html | practice-menu（練習メニュー） | all |
| trumpet-lip-fatigue.html | lip-fatigue（唇のバテ） | trumpet |
| concert-record.html | records（記録・整理） | all |

（現在の記事はこれで全部のはず。ファイル名が増えていたら、同じ考え方で割り当ててください。）
今後の記事は、ブログ用エージェントの記事案に `topic` と `instrument` の項目を足してもらい、
管理者が公開時に `<meta>` へ反映する形にする（記事案の書式の更新は管理者側で）。

### 3. 関連記事（記事の最後）
各記事の本文の下、フッターの上に「関連する記事」を最大3本、1行リスト（009のデザイン）で出す。

- 選び方（優先順）: ①同じ `topic` ／ ②同じ `instrument`（`all` 以外のとき）／ ③新しい順。自分自身は除く。
- 自動更新の方法: 記事に目印のコメントを入れて、`release.py` が毎回その中身を作り直す。
  ```html
  <!-- RELATED:START -->
  ...
  <!-- RELATED:END -->
  ```
  トップの `<!-- BLOG:START -->` と同じ方式。公開のたびに全記事の関連欄が更新される（過去記事のファイルも書き換わる）。
- 見出しは「関連する記事」。記事が1本しかないとき、該当がないときは、欄ごと出さない。
- 外部リンク（`class="src"`）の重複チェックは、関連記事のリンクを数えないよう、`class="src"` を使わず、別のクラス（例 `class="rel"`）にする。

### 4. まとめページを自動生成する
- **テーマ別**: `blog/topic/<topic>.html`（例 `blog/topic/long-tone.html`）。そのテーマの記事の一覧と、
  テーマの短い説明（辞書に1〜2文）を載せる。記事が2本以上あるテーマだけ作る（1本ならページは作らない）。
- **楽器月間の特集**: `blog/instrument/<instrument>.html`（例 `blog/instrument/trumpet.html`）。
  その楽器の記事（`instrument` が一致するもの）をまとめる。`all` のページは作らない。
  毎月第1週の楽器月間特集は、このページが「特集の入口」になる。
- どちらも、ページのHTMLは `INDEX_TMPL` と同じ作りで、009のデザインに合わせる。
  `<title>` と description は固有にする（例「ロングトーンの悩み｜SN Works BLOG」）。
- `sitemap.xml` に、生成したまとめページを追加する（`lastmod` は、そのページに載る最新記事の日付）。

### 5. BLOG一覧ページ（`blog/index.html`）の導線
- 一覧の上部に、絞り込みのリンクを並べる（JavaScriptは使わず、まとめページへの通常のリンク）。
  ```
  悩み別:  ロングトーン / リップスラー / タンギング / 高い音 / ...
  楽器別:  トランペット / ...
  ```
- 記事の数が、現在のように1画面に収まる間は、一覧は今のまま全件を新しい順に並べる。
  20本を超えたあたりから「年・月」で畳む（`<details>` など）ことを検討する。今回は不要。

### 6. 確認項目
- 既存9本の `<meta>` が、表の割り当てどおりに入っている
- 関連記事が、各記事の下に、自分以外の最大3本で出る（トップ・一覧に影響がない）
- 記事が2本以上のテーマだけ `blog/topic/*.html` ができる
- `release.py --no-release` を2回続けて実行しても、差分が出ない（冪等）
- `blog/index.html`、トップの `<!-- BLOG:START -->` 部分が壊れていない
- `class="src"` の重複チェック（`release.py` の中止判定）が、関連記事で誤動作しない
- `sitemap.xml` にまとめページが入っている／URLの形式が既存と揃っている
- `googleb39988c901ff592a.html`、GA4タグ、アイコンのタグは変更しない

### 7. 今回の範囲に含めないもの
- 検索ボックス、前後の記事への移動、目次、読了時間（記事が増えてから別の依頼書で検討する）
- ScoreMateやカレンダーへの誘導の追加（入れる場合も、1行の控えめな案内にとどめる）
- 記事本文や、参考記事のリンクの変更

## 理由・根拠
- 今のBLOGは、新しい順の一覧が1本あるだけで、記事が増えるほど探しにくくなる。
- 記事ごとの `category` は、すでにあるが「コラム／お知らせ」の2種類だけで、悩みや楽器では分けられていない。
- 悩み別（ロングトーン等）と、毎月第1週の楽器月間という運営計画（`_queue/themes.md`）が、そのまま分類の軸になる。
- 関連記事とまとめページで、記事同士のリンクが増え、読者が続けて読みやすくなり、検索からも関連性が伝わりやすい。
- すべてスクリプトの自動生成にできるので、毎週の公開作業は増えない。
